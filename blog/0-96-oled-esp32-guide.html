How I Use an ESP32 with a 0.96-inch SSD1306 OLED

A practical build guide based on the small OLED projects I use for animations, sensors and simple games.

This article is written as a practical maker guide. Project-specific measurements, wiring and test results should always be checked against the actual hardware used for that build.

The hardware I normally start with

My basic setup is an ESP32 development board and a 0.96-inch SSD1306 128×64 I2C OLED. For a quick prototype I use a breadboard and jumper wires. The same display can then be reused for sensor projects, games, clocks and animation experiments.

Wiring the display

The OLED uses I2C, so there are only power, ground and the two I2C signal lines to deal with. On one of my ESP32 setups I use GPIO 21 for SDA and GPIO 22 for SCL. The exact pins can be changed in software on ESP32, so I check the sketch before copying the wiring.

Checking the I2C address

My OLED module commonly appears at 0x3C. If a display stays blank, I don't immediately assume the display is damaged. I first run an I2C scanner, check power and ground, and verify SDA/SCL.

Testing before adding the full project

I always prefer a simple text or bitmap test first. Once the OLED responds, I move to the real animation, sensor or game code. This makes troubleshooting much easier because there is only one new part being tested at a time.

Using the OLED for different projects

The same display becomes very flexible when the graphics code is separated from the project logic. I have used the idea for song animations, sensor status screens, a DINO-style game and other small experiments.

What to watch when making animations

Animation data grows quickly. A 128×64 monochrome frame contains 1024 bytes before the surrounding program and other data are considered. For this reason I keep animation clips short and test memory usage early.
